For the phase-2 profile editor UX, nickname inline validation should use a dedicated lightweight availability API rather than relying only on 409 from profile save. The current backend only validates nickname uniqueness on `PUT /api/user/profile`; there is no separate nickname availability endpoint yet. Preferred future backend addition: a read-only nickname check endpoint for debounced inline validation in the editor. Languages editing should follow the provided popover reference: trigger from the compact languages text in the profile header, open a popover with an informational hint, repeated language rows, each row having a language select + proficiency select + delete action, plus an add-language button at the bottom. Also, future file and component names for this editor area should drop the `user-` prefix from `user-profile-*`; use shorter `profile-*` naming instead.
